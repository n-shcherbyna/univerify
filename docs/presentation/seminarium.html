Motywacja

Problem weryfikacji dyplomów

Stan obecny

  • Rynek fałszywych dyplomów wyceniany na ~$1 mld rocznie
  • Weryfikacja wymaga kontaktu z uczelnią — tygodnie oczekiwania
  • Cross-border: brak interoperacyjności między uczelniami
  • Weryfikator musi bezwarunkowo ufać uczelni

Pytania badawcze

  • Jak zminimalizować koszt przechowywania danych on-chain?
  • Jak chronić prywatność studenta zgodnie z RODO?
  • Która warstwa L2 oferuje najniższy koszt wdrożenia?
Pytanie 1 — Architektura

Jak tanio przechowywać dyplomy on-chain?

Per-record storage

Każdy dyplom zapisany jako osobny slot w storage kontraktu. Koszt rośnie liniowo — n dyplomów = n transakcji.

Merkle-batch issuance

Cały rocznik skompresowany do jednego bytes32 merkleRoot. Koszt stały niezależnie od n — n dyplomów = 1 transakcja.

Weryfikacja: statusWithProof(docHash, proof[]) — publiczna, bezpłatna.

Pytanie 2 — Prywatność

Selektywne ujawnianie danych zgodne z RODO

Problem

Pełna ekspozycja danych

Weryfikacja ujawnia wszystkie pola — imię, ocenę, numer dyplomu. Kolizja z zasadą minimalizacji danych (RODO).

→
Rozwiązanie

Commitments z solą

Każde z 4 pól zastąpione zobowiązaniem kryptograficznym:

cᵢ = keccak256(fieldᵢ ‖ saltᵢ)
docHash = keccak256(c₁‖c₂‖c₃‖c₄)
→
Efekt

Wybór ujawnianych pól

Student ujawnia tylko niezbędne pola. Weryfikator potwierdza ich autentyczność bez wiedzy o pozostałych.

Kontrakt bez żadnych zmian — cała logika prywatności off-chain. Nowa trasa /present w aplikacji webowej.

Pytanie 3 — Benchmarki L2

Które L2 jest najtańsze?

Badane sieci

  • SepoliaEthereum L1 — punkt odniesienia
  • ArbitrumNitro, optimistic rollup
  • BaseOP-Stack (Coinbase)
  • zkSync EraZK rollup

Metodologia

  • 3 niezależne uruchomienia pipeline, zagregowane
  • Rozmiary paczki: n ∈ {1, 10, 100, 1 000, 10 000}
  • Koszt USD modelowany z 90-dniowej historii baseFee
  • N = 30 pomiarów latencji z raportowanym σ
  • Osobny model kosztów L1 per sieć

Architektura Merkle-batch
